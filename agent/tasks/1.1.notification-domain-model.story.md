# Story 1.1: 通知核心模型定义

- 说明：建立 v1 通知数据结构，支持标题、来源、优先级、时间戳、deadline、额外信息、状态。
- 需求来源：`agent/requirements.md` 中「通知数据模型（v1）」。

## 任务

1. 定义 `NotificationPriority` 枚举（低/普通/高/紧急）。
2. 定义 `NotificationStatus` 枚举（Pending/InProgress/Completed/Ignored）。
3. 定义 `NotificationItem` 模型字段：
   - `id`
   - `title`
   - `source`
   - `priority`
   - `timestamp`
   - `deadline`
   - `extraInfo`
   - `status`
   - `unread`
   - `replyDraft`
   - `updatedAt`
4. 定义 `StatusFeedback` 模型：`notificationId/status/comment/timestamp/clientMeta`。
5. 加入可显示字段的计算属性（如 `isOverdue`、`statusText`），用于后续 UI。

## 验收标准

- 所有字段与需求一致，类型可在单元测试中构造。
- 可以在不依赖 UI 的前提下实例化并验证默认值。
- 模型变化不会破坏既有文件的基础编译能力（仅在新建文件范围验证）。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：定义 `NotificationPriority` 与 `NotificationStatus` 枚举（P1，0.5h）
  - 阻塞项：确认 SwiftData 支持的枚举持久化写法。
- T2：定义 `NotificationItem` 核心模型字段与默认值（P1，1h）
  - 阻塞项：无。
- T3：定义 `StatusFeedback` 与 `clientMeta` 结构（P1，1h）
  - 阻塞项：无。
- T4：补充计算属性与辅助方法（如 `isOverdue`）（P2，1h）
  - 阻塞项：依赖 `NotificationItem` 字段设计冻结。
- T5：添加基础单元测试，覆盖模型构造与默认值（P2，1.5h）
  - 阻塞项：测试环境可启动。
