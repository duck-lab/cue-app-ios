# Story 1.2: 通知状态转换与业务语义

- 说明：明确状态转换规则，避免重复提交与非法流转。
- 需求来源：`agent/requirements.md` 中「状态语义」「功能拆分（模块化）」。

## 任务

1. 编写状态转换定义：
   - `Pending -> InProgress | Completed | Ignored`
   - `InProgress -> Completed | Ignored`
2. 将 `Completed` / `Ignored` 作为终态（不做默认回退）。
3. 提供状态转换校验函数，例如：`isTransitionAllowed(from:to:)`。
4. 定义可复用错误码：
   - `invalidTransition`
   - `sameStatusNoop`
   - `missingNotification`
5. 附加测试：覆盖合法/非法转换组合。

## 验收标准

- 非法状态变更会被阻止并返回明确错误。
- 合法变更可推进到下一流程（本地更新 + 后续反馈）。
- 完成/忽略语义在文档与代码注释中保持一致。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：定义状态转换规则与终态策略（P1，1h）
  - 阻塞项：依赖 Story 1.1 的 `NotificationStatus`。
- T2：实现 `isTransitionAllowed(from:to:)` 工具方法（P1，0.5h）
  - 阻塞项：无。
- T3：定义 `DomainError`（invalidTransition / sameStatusNoop / missingNotification）（P2，1h）
  - 阻塞项：与上层错误展示策略对齐。
- T4：补充状态转换单元测试（P2，2h）
  - 阻塞项：测试框架环境可用。
- T5：在业务层文档中记录状态语义（P3，0.5h）
  - 阻塞项：无。
