# Story 3.2: iOS 通知状态操作与备注

- 说明：列表内支持进行中/完成/忽略操作，并可附加可选文本。
- 需求来源：用户处理需求、确认答复信息可选文本。

## 任务

1. 为每条通知添加操作入口（进行中、完成、忽略）。
2. 设计可选备注输入框（或弹出对话）并与提交绑定。
3. 触发状态变化后立即更新列表显示。
4. 提交失败时在 UI 显示可重试状态。

## 验收标准

- 一条通知可在两次操作内完成状态变更。
- 成功变更后列表反映新状态。
- 可选备注随反馈成功提交。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：设计列表内状态操作控件（进行中/完成/忽略）（P1，1.5h）
  - 阻塞项：与需求确认的交互深度一致。
- T2：接入 `ReplyUseCase` 并触发状态变更（P1，2h）
  - 阻塞项：依赖 Story 1.2 与 2.4。
- T3：实现可选备注输入与校验（P1，1.5h）
  - 阻塞项：输入方式与键盘交互体验。
- T4：失败反馈提示与重试入口（P2, 1.5h）
  - 阻塞项：错误文案规范（Story 5.2）。
- T5：状态变更端到端联调（P1，1h）
  - 阻塞项：后端 mock/反馈逻辑可验证。
