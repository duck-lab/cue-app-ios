# 多 Agent 日报看板模板

用于单个 Story 的并行执行过程记录（建议每个 Agent 使用一份）。

## Story 基础信息

- Story：`X.X.story.md`
- 负责人：`Agent-Name`
- 计划开始：`YYYY-MM-DD HH:mm`
- 计划结束：`YYYY-MM-DD HH:mm`
- 当前重试次数：`0 / 1 / 2 / 3`
- 依赖检查：`已满足 / 未满足（列出阻塞项）`

## 状态看板

```text
待开始 -> 进行中 -> 代码实现 -> 本地验证 -> 代码评审 -> Done
                           -> 失败分析 -> 重试-1 -> 重试-2 -> 重试-3 -> BLOCKED
```

## 日志记录（按时间线）

### 记录项（每日）

- `HH:mm`：开始执行，列出 3 个子任务
- `HH:mm`：完成子任务 A/B/C，提交状态变更
- `HH:mm`：阻塞项出现时，记录阻塞来源与证据（日志/截图）
- `HH:mm`：重试原因与修复动作
- `HH:mm`：验收项通过情况

## 重试记录（最多 3 次）

### 尝试 #1

- 触发条件：首次交付
- 结果：通过 / 失败
- 失败原因：
- 修复动作：
- 重试标记：`Retry-1`

### 尝试 #2

- 触发条件：基于 #1 根因修复
- 结果：通过 / 失败
- 失败原因：
- 修复动作：
- 重试标记：`Retry-2`

### 尝试 #3

- 触发条件：保留最小可用方案重构
- 结果：通过 / 失败
- 失败原因：
- 修复动作：
- 重试标记：`Retry-3`

> 3 次仍失败：该 Story 标记为 `BLOCKED`，附带阻塞项转交主控代理。

## 交付内容清单（提交前）

- 代码改动（文件列表）
- 自测命令与结果
- 覆盖的验收条目
- 失败时的日志/截图
- 阻塞项（如仍存在）

## 示例（可直接复制）

- Day1：`8:00` Start -> `11:00` 完成 2 个子任务
- Day1：`14:00` 自测失败（编译错误）-> Retry-1
- Day1：`16:30` Retry-1 通过
- Day1：`17:00` 提交并附验证记录
