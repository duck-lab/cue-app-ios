# Story 2.1: 定义 Notification Repository 抽象层

- 说明：定义统一接口，解耦 UI 与数据源。
- 需求来源：`agent/requirements.md` 中「保留 API 层接口，后续可替换为真实服务」。

## 任务

1. 定义 `NotificationRepository` 协议/接口：
   - `fetchNotifications() -> [NotificationItem]`
   - `submitFeedback(_:) -> Result<Void, Error>`
   - `acknowledge(notificationID)`（可选）
2. 定义 `RepositoryError`，区分网络、解析、超时、鉴权等（预留鉴权）。
3. 使用依赖注入方式在启动时组装默认实现。

## 验收标准

- 业务层仅依赖抽象，不直接实例化具体实现。
- 后续添加真实 API 只需新增实现，不改动上层调用代码。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：定义 `NotificationRepository` 接口与协议方法（P1，1.5h）
  - 阻塞项：依赖 Story 1.1 的模型定义。
- T2：定义 `RepositoryError` 与错误映射（P1，1h）
  - 阻塞项：与错误处理策略（Story 5.2）对齐。
- T3：实现仓库创建/注入入口（P2，1h）
  - 阻塞项：应用启动流程可改造。
- T4：补充仓库协议单元测试替身（P2，1h）
  - 阻塞项：测试基础设施支持。
