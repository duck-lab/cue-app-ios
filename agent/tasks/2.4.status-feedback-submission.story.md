# Story 2.4: 状态反馈接口提交

- 说明：用户状态变更后向系统回传（含可选补充信息）。
- 需求来源：`agent/requirements.md` 中「标记完成或忽略反馈系统」。

## 任务

1. 定义反馈 API 的请求模型（状态 + 可选备注 + `clientMeta`）。
2. 在状态变更入口统一调用：
   - 乐观更新本地
   - 异步调用 `submitFeedback`
3. 实现提交结果处理：
   - 成功：清理待重试标记
   - 失败：落入离线队列
4. 记录反馈请求日志（时间、结果、错误码）。

## 验收标准

- 所有状态变更都能尝试提交反馈。
- 成功/失败可观测。
- 可选备注能随反馈提交。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：定义反馈请求 DTO（状态 + comment + clientMeta）（P1，1h）
  - 阻塞项：依赖 Story 1.3 的 `clientMeta`。
- T2：实现状态变更提交链路（乐观更新 + 异步提交）（P1，2h）
  - 阻塞项：需要仓库接口返回可重试错误。
- T3：补充提交失败处理与重试挂起标记（P1，1.5h）
  - 阻塞项：依赖 Story 2.5 队列模型。
- T4：补充反馈提交测试（成功/失败）与埋点（P2，2h）
  - 阻塞项：测试环境可注入 mock。
