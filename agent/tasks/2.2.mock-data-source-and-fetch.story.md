# Story 2.2: Mock 数据源与初始拉取逻辑

- 说明：暂不接入真实 API 时，使用稳定可验证的 mock 数据。
- 需求来源：`agent/requirements.md` 中「暂时使用 mock 数据」。

## 任务

1. 实现 `NotificationRepositoryMock`：返回固定测试数据。
2. 模拟不同场景：有未读、新消息到达、空列表。
3. 提供注入开关，便于切换 mock 与后续 API 实现。
4. 本地新通知时触发轻量事件，供 UI 更新。

## 验收标准

- 无后端服务也能启动并展示列表。
- 能在开发阶段稳定重放场景（如三种状态都有）。
- Mock 数据字段与要求模型一致。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：定义 `NotificationRepositoryMock` 骨架与数据加载方法（P1，1.5h）
  - 阻塞项：依赖 Story 2.1 的仓库接口。
- T2：编写多场景 mock 数据（空列表、混合状态、有过期项）（P1，2h）
  - 阻塞项：无。
- T3：实现数据切换与刷新事件（P2，1h）
  - 阻塞项：与列表刷新机制（Story 2.3）对接。
- T4：增加 mock 切换能力（配置/环境变量）（P2，1h）
  - 阻塞项：启动配置位置确认。
