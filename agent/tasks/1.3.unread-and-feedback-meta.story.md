# Story 1.3: 未读与反馈元信息定义

- 说明：将 `unread` 设计为独立字段，同时定义客户端反馈元信息。
- 需求来源：`agent/requirements.md` 中「已确认」和「通知更新实体」。

## 任务

1. 明确 `unread` 语义：仅作为菜单栏 badge 计数来源。
2. 明确反馈元信息 `clientMeta` 字段结构（平台、版本、设备）。
3. 设计 `replyDraft` 生命周期：
   - 用户编辑时保留到本地
   - 提交成功后清空
   - 取消时保留至下次操作
4. 将 `unread` 与状态分离：
   - `unread` 变更独立于 `status`。

## 验收标准

- 菜单栏 badge 可直接由 `unread` 聚合，不依赖状态枚举。
- `clientMeta` 在反馈 payload 中可序列化。
- `replyDraft` 可在 UI 回到同一通知时继续展示。

## 开发任务清单（估时 / 优先级 / 阻塞项）

- T1：确认 `unread` 与 `status` 解耦规则并落地定义（P1，0.5h）
  - 阻塞项：与架构确定未读统计口径。
- T2：定义 `ClientMeta` 的结构化字段（平台/版本/设备）（P1，0.5h）
  - 阻塞项：无。
- T3：实现 `replyDraft` 状态管理策略（P1，1h）
  - 阻塞项：依赖相关 UI 编辑态行为确认。
- T4：补充模型层单元测试（P2，1h）
  - 阻塞项：测试编写环境。
- T5：在任务与需求文档中记录字段语义（P3，0.5h）
  - 阻塞项：无。
